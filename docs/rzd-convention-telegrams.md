# Правило 5: конвенциональные телеграммы РЖД

Ветка: `feature/rzd-convention-telegrams`.

Источник ограничений — HASH `telegrams_db` в Redis контейнера `conv-redis` (проект `railconventions`). Оптимизатор **не** парсит тексты и **не** ходит в MSSQL `ConventionalRestriction`: в HASH уже лежат только телеграммы, которые `railconventions` счёл относящимися к компании.

Excel `tmp/КОНВЕНЦИИ_2026.xlsx` на этой машине нет (генерируется на проде). Колонки и текстовый вид строк взяты из `railconventions/src/reporting/excel.rs`; коды ЕСР/ОКПО в Excel **не** пишутся — они только в Redis.

---

## Зафиксированные решения

1. **Empty + конкретная станция назначения.** Закрывать не все Load-узлы станции, а только узлы, у которых совпал **ОКПО или имя** с телеграммой (грузоотправитель и/или грузополучатель узла).
2. **Grain в v1 нужен.** Сопоставлять станцию **назначения груза** в телеграмме со станцией **назначения узла спроса** (`DemandNode.station_to_*`), а не со станцией погрузки. Пример: запрет погрузки зерна на Новороссийск → закрыты все Load-узлы, у которых `station_to` = Новороссийск (эксп.).
3. **«Все станции» без ЕСР.**
   - **Казахстан (КЗХ) и прочие инотерритории** из `ForeignRoads` — **игнорировать**.
   - **Россия:** если запрет на все грузы (`All`) или порожняк (`Empty`) на все станции дороги (нет ОКПО / явно «все грузополучатели» / код станции = «Все станции») — на станции этой дороги нельзя ехать до `date_end`. Конкретная форма в Redis — списки дорог **отправления** и **назначения** (см. пример `4702` ниже), а не одна дорога.

---

## Что лежит в Redis

Это **не** отдельная logical DB, а HASH-ключ в db 0, порт **6379**, bind `127.0.0.1`, пароль `REDIS_CONV_PASS` (Infisical path `/conventions`). Persistence: `/data/conv_dump.rdb`. Это **другой** Redis, чем дислокация `REDIS_SUPPLY_*` (порт 6380).

- Поле HASH = номер телеграммы РЖД (`rzd_number`).
- Значение = JSON `TelegramData`. Старые/истёкшие записи **не** удаляются (`HSET` только добавляет/перезаписывает тот же номер).

### Поля JSON

| Поле | Смысл |
|---|---|
| `rzd_number` | ключ HASH |
| `date_beg` / `date_end` | период запрета (`YYYY-MM-DD`; «до отмены» → `3000-01-01`) |
| `cargo_class` | `Grain` / `Empty` / `All` / `Others` |
| `cargo_name` | текст груза («все грузы», «Порожние вагоны», перечень зерновых) |
| `departure_st` + `departure_st_code` | отправление: имена и/или «Все станции … дорог»; код — 6-значные ЕСР через запятую **или** строка `Все станции` |
| `destination_st` + `destination_st_code` | назначение — то же |
| `recipient_name` + `recipient_okpo` | получатели; `все грузополучатели` / `All` / `Not specified` |
| `railroad_junction` | стык или `None` |
| `convention_info` | почему запись попала в HASH (ГУ-12 / промывка / отстой / ремонт / `Other`). **Не** критерий «запрет действует». Срок — только даты. |
| `text` | сырой текст; процент ограничения (50% и т.п.) **в отдельные поля не выносится** |

Списки станций/получателей — **строка через запятую**, не JSON-массив.

### Как это выглядит в Excel (без кодов)

| Колонка Excel | Откуда |
|---|---|
| № из РЖД | `rzd_number` |
| Дата выпуска | `date_create` |
| Дата начала / окончания | `date_beg` / `date_end` (год ≥ 3000 → «до отмены») |
| Станция, дорога назначения | `destination_st`; если есть стык: `через межгосударственный стык {junction} на {destination_st}` |
| Грузополучатель | `recipient_name` |
| Грузы | `cargo_name` |
| Примечание | текстовая расшифровка `convention_info` |

В Excel **нет** `cargo_class`, ЕСР, ОКПО, станций отправления. Для солвера источник — Redis, Excel только для сверки формулировок.

### Пример HASH (телеграмма 4702)

```json
{
  "rzd_number": "4702",
  "date_beg": "2026-03-03",
  "date_end": "2026-03-04",
  "cargo_class": "All",
  "cargo_name": "все грузы",
  "departure_st": "Все станции Красноярской, Западно-Сибирской, Южно-Уральской и Свердловской железных дорог",
  "departure_st_code": "Все станции",
  "destination_st": "Все станции Октябрьской, Северной, Московской и Горьковской железных дорог",
  "destination_st_code": "Все станции",
  "recipient_name": "все грузополучатели",
  "recipient_okpo": "All",
  "railroad_junction": "None",
  "convention_info": { "type": "Other" }
}
```

Смысл для оптимизатора: запрет **погрузки** со станций дорог отправления **назначением** на станции дорог назначения.

Сопоставление с узлом спроса:

- `DemandNode.railway_name` (погрузка, `RailWayShortFrom`) ∈ {КРС, ЗСБ, ЮУР, СВР}
- **и** `DemandNode.railway_to_name` (назначение груза, `RailWayShortTo`) ∈ {ОКТ, СЕВ, МСК, ГОР}

Это **не** «закрыть всю Октябрьскую для подсыла порожняка». Закрываются только пары «погрузка на одной из дорог A → груз на одну из дорог B».

Маппинг полных имён → коротких кодов уже есть в репозитории: `data/map/supermap_rw_name_to_rw.csv` (например «Октябрьская ЖД» → `ОКТ`). В телеграммах падежи («Октябрьской», «Западно-Сибирской») — нормализовать основу названия.

**Риск 50%.** В тексте 4702 ограничение «на 50% от технического плана», в JSON этого нет. В v1 предлагается трактовать такие записи как **жёсткий запрет** (как вы сформулировали для дорожных конвенций). Если позже понадобится доля — парсить `text` или доработать `railconventions`. На шаге 5 можно пересмотреть.

На дату 2026-09-14 эта телеграмма **истекла** (`date_end` 2026-03-04) — загрузчик обязан отфильтровать её по датам, иначе в HASH копятся мёртвые запреты.

## Что не берём в v1

- Класс `Others` (крытые, цистерны, фитосанитария), кроме записей промывки/ремонта/отстоя (их класс в HASH часто `Others` — трактуем как Empty).
- Повторный LLM / MSSQL.
- Запись в `telegrams_db` из оптимизатора (только чтение).
- Истёкшие / ещё не начавшиеся / без дат — HASH читается целиком (`HGETALL`), но в память и снимок не кладутся.
- Глобальные «все станции КЗХ / Казахстан». Остальные инотерритории (БЕЛ, УЗБ, …) применяются.

## Правила матчинга v1 (после импорта)

`DemandPurpose::Load`, а также назначения в промывку, ремонт и отстой (`WashingStation` / `RepairStation` / `ReserveStation`). Место — `classify_pair` → новый `PairOutcome::ConventionBan`. Дуги нет, пока действует `date_beg…date_end` (горизонт планирования: сегодня … сегодня+14 суток; `date_end >= сегодня`, `date_beg <= конец горизонта`).

### А. Конкретные ЕСР назначения

Списки кодов из `destination_st_code` (6 цифр), имена — запасной ключ (как «Новороссийск эксп.»).

| `cargo_class` | Что закрываем | Сторона узла спроса | Сторона контрагента |
|---|---|---|---|
| `Empty` | подсыл порожняка **на станцию погрузки** | `station_code` / `station_name` | только узлы с совпавшим ОКПО **или** именем: `sender` / `sender_okpo` и `recipient` / `loader_to_okpo` vs `recipient_*` телеграммы |
| `Grain` | погрузка **назначением** на станцию запрета | `station_to_code` / `station_to_name` | в примере Новороссийска — **все** узлы с этим назначением; если в телеграмме конкретный получатель (не `All`) — сужать по `recipient` / `loader_to_okpo` |
| `All` | оба эффекта | и станция погрузки, и станция назначения груза | Empty-ветка — с фильтром ОКПО/имени; Grain-ветка — как Grain |

Если `recipient_okpo == All` или имя «все грузополучатели» — для Empty/All на конкретной станции фильтр по контрагенту **не** отключает запрет целиком: для Empty на ЕСР вы просили только совпавшие ОКПО/имена. Уточнение на шаге 5: при `All` + конкретный ЕСР закрывать все узлы станции или всё же требовать контрагента? Сейчас в плане: **конкретный ЕСР + Empty → только совпавший контрагент**; **конкретный ЕСР + Grain → все узлы с этим `station_to`**, если получатель телеграммы `All`.

### Б. Без ЕСР: «Все станции» дорог РФ

Код станции = `Все станции` (нет цифр ЕСР). Разобрать имена дорог из `departure_st` и `destination_st`. Из инотерриторий выкидывается только **КЗХ**; БЕЛ, УЗБ и прочие остаются. Если после снятия КЗХ список назначения пуст — телеграмму не применять.

| Списки дорог | `Empty` | `All` (и «все грузы») |
|---|---|---|
| только назначение (отправление пустое / «все станции» без списка дорог) | нельзя подсылать ни на какие станции этих дорог: `DemandNode.railway_name` ∈ dest | то же для подсыла **и** запрет гружёного назначения: `railway_to_name` ∈ dest |
| только отправление | не закрываем «всю дорогу назначения»; для Empty обычно не про подсыл «на» | запрет погрузки с этих дорог на любые назначения: `railway_name` ∈ dep |
| оба списка, как 4702 | подсыл на станцию погрузки дороги dest **только если** груз узла едет на dest? Для Empty без направления груза — осторожно: v1 для Empty+оба списка трактовать как запрет подсыла на dest-дороги **с** станций dep-дорог (`SupplyNode.railway_to` ∈ dep и `DemandNode.railway_name` ∈ dest) | как в 4702: `railway_name` ∈ dep **и** `railway_to_name` ∈ dest |

Получатель `All` / нет ОКПО — условие дорожного правила (ваш ответ). Если в дорожной телеграмме вдруг указан конкретный ОКПО — сужать как в пункте А.
